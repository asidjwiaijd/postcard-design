# 社团明信片工坊

给社团招新 / 漫展物料用的在线明信片设计站。米娜自己上传喜欢的角色图、写想说的话、
排好正反两面，提交后你在后台审核，通过的统一打包拿去印。

- 拖拽式编辑器，正面 / 反面分开设计，18 套整页模板 + 元素块
- **每一面可以各自选横版 / 竖版**，模板会按当前朝向自动排版
- 一人可以同时留 **20 份未提交的稿子**，「新建」之后随时回到之前那张
- **照片位（剪贴蒙板）**：模板里的虚线形状双击就能选图，图自动按爱心 / 拱门 / 邮票齿孔等 15 种形状裁好
- 桌面端可**框选多个元素**，整组拖动、对齐、批量删除；Shift 点选加选
- 反面可选国内明信片、日式年贺状等**邮政底纹**（邮编格 / 邮票框 / 地址线）
- 首页是**实时作品墙**，谁交了稿十几秒内自己刷出来，带累计张数和参与人数
- `/wall` 是**斜着流动的大屏分享页**，摊位上挂个屏幕就行
- 可以设**全站最多收多少张**，收满之后自动停止收稿
- 进编辑器先弹一次**设计须知**：出血 / 安全区示意图 + 内容规范（版权、涉黄涉暴、隐私）
- 邀请链接 + QQ 号登录，无需注册，可限制每人张数
- 提交后服务端按 **300dpi 含出血**渲染，自动压到每面 3MB 以内的 WebP
- 上传的素材也会**转正、限长边、压到目标体积**（默认 2600px / 1.25MB）再入库
- 用户随时下载自己的成品；管理员审核后一键打包成印刷用 zip
- 移动端可用，整体二次元风格

## 快速开始

```bash
cp .env.example .env
# 至少改这两项：
#   ADMIN_PASSWORD  后台密码
#   SESSION_SECRET  openssl rand -base64 32

docker compose up -d --build
```

打开 `http://服务器:3000/admin`，用 `ADMIN_PASSWORD` 登录 → **邀请链接** → 生成一条，
把 `https://你的域名/i/xxxxxxx` 发到群里或做成二维码贴摊位上。米娜点开、输 QQ 号就能开始画。

本地开发：

```bash
npm install
npm run dev        # http://localhost:3000
npm run check      # 类型检查 + 模板版面体检
```

## 配置都在后台改

除了**后台密码**、**会话密钥**和**数据目录**这三项（它们在进程启动前就要用到，
只能写在 `.env`），其余所有设置都在 `/admin` → **设置** 页里改，存数据库，
重启和重新部署都不会丢。`.env` 里的同名变量只是**第一次启动时的默认值**，
后台改过之后就不再起作用；想让它们重新生效，在设置页点「恢复默认」。

必须写在 `.env` 的三项：

| 变量 | 说明 |
| --- | --- |
| `ADMIN_PASSWORD` | 后台密码。生产环境不设置就无法登录后台 |
| `SESSION_SECRET` | 会话签名密钥，`openssl rand -base64 32` 生成；改动后所有人重新登录 |
| `DATA_DIR` | 数据库 + 所有图片，容器里已挂成卷。做备份就备份这一个目录 |

后台可改的（括号里是默认值）：

| 分组 | 项目 |
| --- | --- |
| 明信片规格 | 成品宽高（148×100mm）、出血（3mm）、安全区（4mm）、分辨率（300dpi） |
| 限额 | 每人提交张数（3）、**全站最多收（0＝不限）**、素材上传张数（30）、单张上传上限（20MB）、上传图最长边（2600px）、**素材入库目标体积（1.25MB）**、成品单面目标体积（3MB）、提交原图硬上限（60MB） |
| 站点文案与首页 | 站点名、社团名、提交后是否立即可下载、首页是否展示作品墙、作品墙是否只放已通过的 |

### 尺寸要趁早定

默认导出 **154 × 106 mm / 1819 × 1252 px**（含出血）。尺寸虽然随时能改，
但改完之后：

- 已提交的成品图不会变，和新规格混在一起就没法一起下印
- **未提交的草稿会被判作废**，米娜下次进编辑器是一张白纸
- 自带模板是按 148×100 横版排的，换比例后跑一次 `npm run check`，
  它会按当前生效的规格验一遍，告诉你哪些模板的文字跑出了安全区

所以有人开始交稿之后就别再动了。后台在检测到这类改动时会要求勾选确认。

## 使用流程

**给米娜的：** 点邀请链接（登录页就列了几条底线）→ 输 QQ 号确认头像昵称 →
第一次进编辑器会弹一次「设计须知」（出血、安全区、内容规范，看过记在本地，
电脑顶栏的问号、手机「模板」面板里的「设计须知」可以随时翻回来）→ 选模板 → 双击照片位放图、改文字 → 提交 →
立刻能下载自己那张，同时进入待审队列。草稿自动保存，关掉再回来还在。
顶栏的「＋」可以新建一张、**回到之前没交的那几张**（最多留 20 份），
也可以挑一张自己交过的稿子复制出来接着改。
每一面的朝向（横 / 竖）在模板面板顶部和顶栏都能换（手机顶栏上是一个图标按钮），
换完会问要不要把已排好的内容一起转 90°。
手机上：空白处单指拖 = 框选，双指 = 缩放和平移；选中元素后底部快捷栏里有
「转 90°」和「锁长宽比」，属性面板里还有「还原原图比例」。
电脑上 Ctrl / ⌘ + 滚轮也能绕光标缩放。

**给你的（后台 `/admin`）：**

- **稿件审核** — 缩略图列表，点开看正反面大图，通过 / 拒绝（拒绝理由会显示在作者的作品页）、
  标记已印、删除。右上角**打包下载**导出当前筛选状态的全部稿件。
- **邀请链接** — 按场次生成（招新 / 漫展各一条，方便回头看是哪批人来的），
  可设可用人数、每人张数、有效期，随时停用。
- **社团素材** — 上传 Logo、吉祥物立绘等，米娜在编辑器「贴纸 → 社团素材」里就能用。
- **用户** — 搜索、单独调整张数额度、停用。

大屏分享页在 `/wall`：整屏斜着流动的作品瀑布 + 实时提交数，摆摊时投到显示器上正好。

导出的 zip 结构：

```
001_昵称_QQ号/正面.webp
001_昵称_QQ号/反面.webp
...
清单.csv        # UTF-8 BOM，Excel 直接打开
印刷说明.txt     # 尺寸、出血、色彩空间，发给印厂
```

## 技术栈与实现要点

Next.js 15（App Router）+ React 19 + Tailwind v4 + Konva 画布 + Node 内置 `node:sqlite` + sharp。

几个值得知道的设计决定：

- **坐标单位是毫米**。文档里所有几何量都是物理尺寸，与屏幕分辨率无关；
  导出时只是把画布 scale 换成 `300dpi ÷ 25.4`，因此预览和成品严格一致。
- **导出只导内容层**。参考线和变换手柄在独立的 Konva 图层上，成品天然不会带上它们。
- **导出前显式等字体**。Canvas 不像 DOM 那样会自动触发 webfont 下载，
  `lib/fonts.ts` 的 `ensureFonts()` 会按实际用到的文字调 `document.fonts.load`，
  否则 300dpi 成品会悄悄退化成系统兜底字体。
- **Cookie 的 Secure 看浏览器的 Origin，不看 `x-forwarded-proto`**。
  腾讯云 EdgeOne 这类 CDN 不管访客用 http 还是 https，回源一律写
  `x-forwarded-proto: https`；只信这个头就会给 http 访客发 Secure cookie，
  浏览器直接丢掉，表现是「登录接口返回 200，页面却一直停在登录框」。
  cookie 只在 POST 里下发，同源 POST 一定带 Origin，所以以浏览器写的
  Origin / Referer 为准，两头都没有才退回 `x-forwarded-proto`。
  要强制指定还是用 `COOKIE_SECURE=true/false`。
- **头像走同源代理**（`/api/qq/avatar/[qq]`）。直接引 `q.qlogo.cn` 会污染画布，导致导不出图；
  代理同时把头像缓存到本地，印刷时不会掉图。
- **压缩是二分质量**。成品面和用户素材共用 `encodeUnderTarget()`：先试最高质量，
  超标了按超标倍数估一个起点再二分几轮，在不超过体积上限的前提下取最高画质。
  成品面实测满版随机噪点（最坏情况）压到 2.3MB / 1.7 秒；素材是用户干等的路径，
  effort 和轮数都调低了，12MP 细节照片实测 5.5MB → 1.16MB / 7 秒，
  一般照片一次就过（约 2 秒）。
- **底纹和矢量素材全是代码生成的 SVG**，无版权风险、可任意换色，
  按元素实际毫米宽度决定栅格化尺寸，印刷时不糊。
- **存储是适配器**（`lib/storage.ts`）。现在落本地磁盘，要换 S3 / R2 / OSS 只需另写一个实现。
- **蒙板形状只写一份**（`lib/frames.ts`）。路径画在 0~1 的单位正方形里，
  画布侧喂给 `Path2D` + `DOMMatrix` 交给 Konva 的 `clipFunc`，DOM 预览侧塞进
  `<svg viewBox="0 0 1 1">` 的 `clipPath`，两边共用同一串 `d`。
- **触屏手势自己接管**。双指缩放/平移挂在画布容器上（`useCanvasGesture`）：
  手势过程中只改 CSS `transform`，松手才把倍率并进 `zoom`。Konva 的 scale 是
  React 属性，跟着手指改等于每帧把整棵元素树重渲一遍，手机上根本跟不上手。
  卡片在可视区里居中，CSS 缩放和改 zoom 都是绕同一个中心放大，并进去的那一下不会跳。
  第二根手指落下时会取消正在进行的框选和元素拖动（元素放回原位），
  这条 effect 要等 `<main>` 挂上来才能绑，`ready` 参数就是为了这个。
- **框选和吸附线都不走 React**。每帧 `setState` 会重渲整棵元素树；
  选框和两条吸附线是常驻的 Konva 节点，拖动时只改坐标 + `batchDraw`。
  吸附线单独一层，免得连带重画整层参考线。
- **拖动时吸附了要 `tr.forceUpdate()`**。Konva 的 Transformer 在拖动中是被
  `_proxyDrag` 按指针位移带着走的，不看节点实际落在哪；我们在 `dragmove` 里
  把节点吸到参考线上之后，选框会正好差出吸附的那一点距离，必须手动刷一次。
  多选整组拖动时干脆不吸附，否则每个元素各吸各的会把队形拆散。
- **触屏上把 `Konva.pixelRatio` 封到 2**。手机 DPR 常见是 3，拖动时每帧要多填
  一倍多的像素。导出走 `export.ts` 自己带 pixelRatio，不受这里影响。
- **Konva 的 Transformer 用绝对坐标定位**，不吃所在图层的缩放——手柄尺寸要写屏幕像素，
  除以画布 scale 会让手柄缩成两三个像素，几乎点不到。
- **朝向是每一面各自的属性**（`SideDoc.turned`），不是整张卡的。
  版面尺寸一律走 `lib/config.ts` 的 `pageW()/pageH()`，直接用 `bleedW()/bleedH()`
  会把竖版页画成横的；模板和底纹里的 `pw()/ph()` 也是同一回事。
  两面朝向不一致时提交前会提醒，导出清单里逐张标了朝向。
  入口有两处：顶栏（窄屏收成一个图标按钮）和模板面板顶部那一行。
- **作品墙的每一列都要比可见高度长**。列内容复制一份、动画走到 -50% 接回开头，
  「一份」短于屏幕高度的话滚到一半下面就露白了——`GalleryFlow` 按实测容器尺寸
  算每列至少铺几张。列里的图也不能 `loading="lazy"`：转过角度的容器里浏览器
  判定它在视口外就不加载，图没高度整列会塌。
- **界面不用 emoji**，全部走 `components/ui/icons.tsx` 里的内联 SVG：
  emoji 在 Windows / 安卓 / iOS 上是三套画风，基线和字重也对不齐。

## 运维

**备份**：整个 `./data` 目录就是全部状态（SQLite + 所有图片）。
数据库开了 WAL，热拷贝请连 `app.db-wal` 一起拷，或者更稳妥地先 `docker compose stop`。

```bash
docker compose stop
tar czf postcard-backup-$(date +%F).tar.gz data/
docker compose start
```

**目录属主**：容器内以 uid 1001 运行，启动时会把挂载目录 chown 成 1001。
想让它跟宿主用户一致，在 compose 里加 `PUID` / `PGID` 环境变量即可。

**反向代理 / CDN**：前面挂 Nginx / Caddy 时注意放开上传体积——
提交一张明信片会 POST 两张 300dpi PNG，给到 `client_max_body_size 100m` 比较稳妥。
挂在 CDN（EdgeOne / 阿里云 CDN 之类）后面时：确认 `/api/**` 不被缓存、
Set-Cookie 和 Cookie 头要透传，建议直接在 CDN 上开「强制 HTTPS 跳转」。

## 已知边界

- 图片链接是不可猜的随机 key，默认不做逐请求鉴权：拿到链接的人就能看到图。
  社团物料这个场景够用。把后台的「提交后立即可下载」关掉之后，未通过审核的
  成品会真的挡住（只有管理员能取），但已通过的仍然是纯随机 key 保护。
- **首页作品墙和 `/wall` 分享页都是公开的**：没登录的人也能看到缩略图和昵称
  （QQ 号和头像不露，因为头像地址里就带着 QQ 号）。不想公开就在后台关掉
  「首页展示作品墙」（`/wall` 会跟着关），或者打开「只放已通过的」先过一遍审核。
- **「全站最多收」不是强事务**：并发提交时理论上可能多收一两张（落盘前会再查一次，
  窗口只剩几毫秒）。社团这个量级不用管，真要卡死就把它设成比目标小一点。
- **两面朝向不一样的稿子**印的时候得把其中一面转 90°。提交前会提醒作者，
  导出的清单里也逐张标了朝向，拼版时照着看。
- 配置存在数据库里、缓存在进程内存里，多实例部署时改完配置只有处理那个
  请求的实例立刻生效，其余实例要等重启。单机部署没有这个问题。
- 输入 QQ 号不做实名校验，靠邀请链接控制入口 + 后台审核兜底。
- **头像能自动抓到，昵称不能**。腾讯的 `cgi_get_portrait.fcg` 现在要登录态，
  只会返回 `need login`，所以登录时让用户自己填昵称（这个名字会进模板）。
  代码里的抓取逻辑保留着，哪天接口放开就自动生效。
- 限流是进程内的，单机部署没问题；将来要多实例得换成 Redis。
- 输出是 sRGB。要 CMYK 请让印厂统一转，前端转 CMYK 反而容易出偏色。
